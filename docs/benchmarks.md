## エージェント評価 (自作ハーネス、計 48 タスク)

`llama-server --jinja` の OpenAI 互換 tool calling に対して実施。

| ラウンド | 内容 | Q4_K_S | Q2_K_XL |
|---|---|---|---|
| 1 (24) | 単純選択 / 曖昧な弁別 / 引数抽出 / 呼ばない判断 | 24/24 | 24/24 |
| 2 (12) | 複数ターン連鎖 / 並列呼び出し / 情報不足 / 注意逸らし / エラー回復 | 12/12 | 11/12 |
| 3 (12) | 情報不足のみ拡充 | 11/12 | 11/12 |
| **合計** | | **47/48** | **46/48** |

**9.83GB まで削ってもエージェント能力は落ちない。** 48 タスクで検出可能な差なし。

### 実用値

```
1 ターン        3 〜 15 秒 (平均 7 〜 8 秒)
生成トークン     136 〜 197
thinking トークン  0        ← tool calling 時に <think> を出さない
10 ステップ      約 70 秒
```

多くの推論モデルは毎ターン推論トークンを払うが、このモデルは払わない。

### モデル自体の弱点

**時刻が未指定だと 10:00 を捏造する** (両量子化で同一)。

```
"Schedule a retro called Sprint Retro on 2026-12-01."  → start_time=10:00
```

他 11 種類の欠落 (宛先 / 送金先 / 送金額 / 出発地 / 到着地 / 元通貨 / 変換先 /
金額 / 日付 / 本文 / リマインダ時刻) では正しく聞き返す。
**エージェント運用では時刻の既定値を禁止するシステムプロンプトが要る。**

## 実用性

### 持続負荷 (25 分 / 255 生成、llama-server 常駐)

```
decode     25.28 → 25.13 t/s (-0.6%、ノイズ範囲)
sclk       1773 - 1801 MHz 維持
junction   最高 96C (スロットリング閾値 110C)
VRAM       14702 MB 安定、クラッシュなし
```

**定期再起動は不要。** VRAM 断片化はプロセスの繰り返し起動で蓄積するもので、
常駐プロセス内では発生しない。

### 文脈長スケーリング (UD-Q3_K_XL, -c 49152)

| 深さ | prefill | decode |
|---|---|---|
| 8192 | 174.07 | 20.98 |
| 16384 | 158.63 | 20.29 (-3.3%) |
| 32768 | 140.94 | 18.21 (-13.2%) |
| 45000 | 130.68 | 18.40 (-12.3%) |

**文脈 5.5 倍で decode 劣化 12%。** 混合アテンションの実利。
prefill は -25% でより大きいが、16 層の full attention の二次コストとして想定内。
