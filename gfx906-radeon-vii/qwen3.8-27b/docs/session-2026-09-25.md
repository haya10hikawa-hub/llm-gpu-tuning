# 2026-09-25 セッションログ: decode のカーネル別内訳と HVV 効果の齟齬

GPU は同時間帯に Bonsai-2-27B (別モデル、三値量子化、Gated DeltaNet 48層) の
エージェント評価に数時間占有されていたため、本セッションの新規最適化は
GPU 未検証のまま記録する。速度に関する主張は含めない。

## 再確認: 施策4 (HOST_VISIBLE_VIDMEM) は本番導入済み

`/etc/llm-api.env` に `GGML_VK_DISABLE_HOST_VISIBLE_VIDMEM=1` が既に設定されて
いることを確認した。本番と同一引数 (`-c 32768 --parallel 1 -ctk q8_0 -ctv q8_0
-b 512 -ub 256`) で再測定し、深さ 4.3k / 25.9k の両方で貪欲生成の出力が完全
一致することを確認した (設定変更はしていない)。

## 齟齬: このセッションの効果量が findings.md の記録より大きい

| | このセッションの実測 | findings.md #4 |
|---|---|---|
| baseline decode (変数なし) | 約10.0 t/s (深さ4.3k) / 9.6 t/s (25.9k) | 21.77 t/s |
| HVV 有効 | 25.0 t/s / 22.0 t/s | 26.11 t/s |
| 倍率 | 2.3〜2.5倍 | +20% |

HVV 有効後の値はほぼ一致する (25.0 / 22.0 vs 26.11) が、**変数なしの baseline
がこのセッションでは半分以下**。原因はおそらく `AGENTS.md` の「VRAM 断片化」
ハザードで、本セッションは数時間にわたり Bonsai-2-27B / MiMo / 本ログのカーネル
計測用に `llama-server` を数十回起動・終了しており、host-visible の 256MB
ヒープ (HVV バグの当事者そのもの) がより深く断片化した可能性がある。

**規約9 (1件の差を結論にしない) に従い、この齟齬を理由に findings.md の数値
は書き換えない。** GPU が空いた直後・他プロセスの起動履歴がない状態で対照を
挟んで再測定することを次回セッションへの申し送りとする。

## 新規計測: decode 1 トークンのカーネル別内訳 (`GGML_VK_PERF_LOGGER=1`, HVV有効)

本番と同一引数、深さ約4.3k で 63 グラフを平均。1トークンあたり GPU 合計
39.55ms、起動 1731 回。

| 区分 | ms/token | 割合 | 実効帯域 |
|---|---:|---:|---:|
| 量子化 matvec 計 | 29.48 | 74.5% | 490 GB/s (加重平均) |
| ├ iq4_xs | 12.79 | 32.3% | 492 GB/s |
| ├ q4_K / q5_K / q6_K | 11.12 | 28.2% | 584〜614 GB/s |
| └ iq3_s / q3_K | 3.27 | 8.3% | **287 / 362 GB/s (最も低い)** |
| 残りの小さな演算 (約1,234回) | 10.08 | 25.5% | 平均 8.2 us/回 |

小さな演算のうち、再帰状態の読み書き (GET_ROWS 97回 + CPY 96回) は
**1.84ms = 4.65%**。これは `rejected.md` の「クリーン状態では 3.3%」に近く、
同ファイルが警告する「36.6% という断片化アーティファクト」ではないことを
裏付ける一点になる (相互検証)。

## 保留中の最適化案 (単体テストのみ合格、速度は未計測)

四つの変更を試作し、`test-backend-ops test` での正当性確認のみ済ませた
(いずれも GPU が Bonsai 評価で埋まっていたため速度計測は次回)。

1. **iq4_xs matvec**: 1バイトから2値を引く LUT を byte 単位に変更し、共有
   メモリ読み出しと命令数を半減。correctness 14/14。
2. **rms_norm**: サブグループ和 + 入力とスケールをレジスタに保持。融合版
   (`RMS_NORM_MUL_ADD` / `RMS_NORM_MUL_ROPE` / `ADD_RMS_NORM` 含む) すべて
   correctness 合格 (51+36+222+25 = 334/334)。
3. **qwen35 グラフ**: q/k の L2 norm を1回のビューにまとめ、alpha の
   `ADD(ssm_dt)` を reshape の前に動かして matvec+ADD 融合を効かせ、
   `ssm_out` を先に2次元化して出力側の reshape を消す。見積り −192起動/token。
4. **再帰状態の恒等コピー**: 単一系列・ロールバックなしのときだけ、状態の
   `GET_ROWS` をキャッシュ行への直接ビューに置き換える。見積り −96起動/token。

**(4) は `rejected.md` の「再帰状態の in-place 化: 着手せず」に対応する試作
だが、同項目はクリーン状態で 3.3% しか無いと明記されている。(3)(4) 合計の
見積り (約1.9ms) は測定前の静的見積りであり、規約6 により実測範囲内に収まる
保証はない。** 環境変数1つで元に戻せる (`LLAMA_QWEN35_GRAPH_ORIG=1`,
`LLAMA_RS_VIEW_DISABLE=1`)。
